В этой главе описано, чему учит дисциплина и чем она отличается от классического плана. Весь курс студенты пишут на C одну программу — агент, который следит за состоянием компьютера с Windows. На каждой паре агент получает новую возможность, а на многих — новую проверку; к концу курса проверок тринадцать. Тревоги агента уходят в сервис автоматизации n8n, где модель ИИ пишет объяснение для человека. Глава заканчивается заданием к модулю 0 — первой программой на WinAPI.

§1Чему учит дисциплина

Дисциплина длится 24 пары. За это время невозможно научиться писать драйверы или ядро, поэтому цель другая: понять, что происходит внутри Windows, когда работает программа, научиться получать эти сведения из своего кода и проверять их служебными программами. Все темы курса — процессы, память, файлы, реестр, сеть, службы — собираются в один проект, который к концу семестра работает как настоящий агент мониторинга.

После дисциплины студент должен уметь пять вещей:

  1. Объяснить, что происходит внутри Windows во время работы программы: процессы и потоки, виртуальная память, файлы и реестр, сетевые соединения, службы.
  2. Писать на C программы, которые вызывают WinAPI, и разбирать ошибки этих вызовов по кодам GetLastError.
  3. Проверять результат служебными программами: Process Explorer, Process Monitor, Autoruns, TCPView, отладчиком x64dbg.
  4. Связывать системную программу с сервисами: отправлять данные в n8n, подключать модель ИИ, оценивать, сколько ресурсов она занимает.
  5. Защитить проект: показать агент в работе, объяснить любую строку кода и найденные им нарушения.

§2Классический план и план курса

В классическом плане этой дисциплины лекции пересказывают теорию операционных систем, а практика проходит в Windows Forms. Windows Forms — библиотека .NET для окон, кнопок и списков. Она берёт обращения к системе на себя: строка Process.GetProcesses() возвращает готовый список процессов, а как Windows его собирает, программист не видит. В результате теория остаётся текстом лекции, а практика учит располагать элементы на форме, то есть прикладному программированию.

Сравнение из жизни

Пультом от телевизора пользоваться удобно, но по нему не узнать, как устроен телевизор. Чтобы разобраться, нужно снять заднюю крышку и проверить плату прибором. Windows Forms — это пульт. В курсе роль снятой крышки играет WinAPI, а роль прибора — программы Sysinternals и отладчик.

Снятая крышка телевизора лишает гарантии, а вызовы WinAPI — обычный способ работы с Windows, им пользуется сама Microsoft.

В курсе каждая тема теории проверяется на настоящем компьютере. В таблице одна и та же тема в двух планах.

§3Проект: агент-сторож компьютера

Агент мониторинга — программа, которая постоянно работает на компьютере, собирает сведения о его состоянии и сообщает о нарушениях. Такие программы есть в каждой организации, где больше нескольких компьютеров: агент Zabbix следит за нагрузкой серверов, Защитник Windows — за подозрительными файлами, системы инвентаризации — за установленными программами.

Сравнение из жизни

Охранник обходит здание по маршруту и сверяет увиденное со списком правил: окна закрыты, посторонних нет. При нарушении он звонит дежурному. Дежурный уточняет подробности и сообщает начальнику понятными словами, что случилось и что делать.

Охранник обходит здание раз в час, а агент получает часть событий от Windows сразу, без обхода: изменение ключа реестра, новый файл в папке.

В курсе агент на C следит за процессами, памятью, файлами, реестром, сетью и журналами Windows. Когда он замечает нарушение, он отправляет описание в сервис автоматизации n8n. Там модель ИИ пишет объяснение для человека, и уведомление приходит на почту или в таблицу. Ниже путь одной тревоги: программа прописала себя в автозагрузку через реестр.

Системное программирование занимает первые два звена: агент должен заметить изменение в реестре и передать его по сети. Звенья n8n и ИИ подключаются в модуле 4, когда агент уже умеет отправлять HTTP-запросы. Каждое звено студент собирает сам и проверяет отдельно.

Агент растёт от пары к паре. Как это проверяется — в следующем разделе.

§4Как растут проверки

Сравнение из жизни

Инструктор по вождению сначала проверяет только трогание с места, потом добавляет повороты, парковку, движение в потоке. На экзамене маршрут включает всё сразу, и трогание с места из него не исчезает.

На экзамене по вождению маршрут один, а здесь нарушитель после каждой пары получает новую ситуацию, и старые ситуации проверяются заново.

Работу агента проверяет не только преподаватель. В репозитории студента настроен GitHub Actions — автоматический запуск на сервере GitHub с Windows. После каждой отправки кода сервер собирает агент и запускает программу-нарушитель. Нарушитель по очереди создаёт ситуации из пройденных тем: запускает процесс, который загружает процессор, меняет файл hosts, добавляет запись в автозагрузку. Агент должен заметить каждую. После каждой пары у нарушителя появляется новая ситуация, поэтому новая проверка не должна сломать старые.

Ползунок ниже выбирает пару. Цветная полоса под клеткой — модуль, ромбик над клеткой — пара, на которой появляется новая проверка.

После модулей 2, 3, 4 и 5 проходит тест по их темам — на парах 8, 12, 18 и 22. Курсовая работа собирается из агента со всеми проверками, поэтому к паре 23 она почти готова: остаётся добавить одну свою проверку, отчёт и защиту.

Что нужно для работы

Windows 10 или 11, права администратора: они нужны для служб, журнала безопасности и Process Monitor. Оперативной памяти — от 8 ГБ: на 8 ГБ работает модель на 1–3 млрд параметров, на 16 ГБ — до 8 млрд. Модели и программы для кабинета скачиваются заранее и раздаются из общей папки, поэтому на паре интернет нужен только для GitHub. OpenAI и Anthropic не работают с российскими адресами, поэтому в курсе используются локальная модель и российские облачные модели.

§7Задание к модулю 0

Первая программа на WinAPI · сдаётся файлами hello.c и report.md

Нужно установить компилятор, собрать программу из главы 0.1 и найти её процесс в Диспетчере задач по номеру, который она напечатает.

  1. Установите компилятор

    Откройте страницу visualstudio.microsoft.com/downloads, в разделе Tools for Visual Studio скачайте Build Tools for Visual Studio. В установщике отметьте рабочую нагрузку Разработка классических приложений на C++ (Desktop development with C++) и нажмите Установить. Если компилятор в кабинете уже установлен, переходите к шагу 2.

    Место под кадр с компьютера в классе

    Visual Studio Installer, вкладка «Рабочие нагрузки»: отмечена «Разработка классических приложений на C++», справа в списке компонентов отмечены MSVC и Windows 11 SDK.

  2. Откройте командную строку компилятора

    В меню «Пуск» найдите x64 Native Tools Command Prompt for VS. В этой командной строке настроены пути к компилятору; в обычной командной строке и в PowerShell команда cl не найдётся.

  3. Создайте файл программы

    Выполните команды и вставьте в Блокнот код ниже. Блокнот спросит, создать ли новый файл, — ответьте «Да».

  4. Скомпилируйте программу

    Первая строка вывода — название и версия компилятора, например Microsoft (R) C/C++ Optimizing Compiler Version 19.44…. Старший номер 19 у компилятора MSVC начиная с Visual Studio 2015. В папке появятся файлы hello.obj и hello.exe.

  5. Запустите программу и найдите её процесс

    Программа напечатает строку agent v0, pid=… и будет ждать Enter. Пока она ждёт, откройте Диспетчер задач, вкладку Подробности, найдите hello.exe и сравните число в столбце ИД процесса с числом в выводе. Затем нажмите Enter в командной строке.

    Место под кадр с компьютера в классе

    Слева командная строка с выводом «agent v0, pid=…», справа Диспетчер задач на вкладке «Подробности», строка hello.exe с тем же ИД процесса выделена.

Отчёт report.md содержит три строки: первую строку вывода cl, первую строку вывода hello.exe и ИД процесса из Диспетчера задач. Запустите программу второй раз и допишите четвёртой строкой новый номер: он будет другим, потому что Windows выдаёт номер при каждом запуске процесса. Файлы hello.c и report.md войдут в репозиторий курса на паре 2.

Если компилятор пишет, что не находит windows.h

В установщике не отмечен Windows SDK. Откройте Visual Studio Installer, нажмите «Изменить» у Build Tools и отметьте в рабочей нагрузке C++ пункт Windows 11 SDK.

Итог главы

Дисциплина учит понимать, что происходит внутри Windows во время работы программы, получать эти сведения из кода на C через WinAPI и проверять их служебными программами. Вместо форм Windows Forms студенты весь курс пишут агент мониторинга. Каждая пара проходит три шага: вызов WinAPI, сверка со служебной программой, новая проверка агента. За 24 пары агент получает 13 проверок, и нарушитель в GitHub Actions проверяет их все после каждой отправки кода. С модуля 4 тревоги агента уходят в n8n, где модель ИИ пишет объяснение для человека. Курсовая работа — агент со всеми проверками, одной своей проверкой и защитой.
