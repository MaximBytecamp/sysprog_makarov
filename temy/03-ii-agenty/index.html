§1Чат, помощник и агент

Инструменты ИИ для программиста различаются тем, сколько они делают сами. Чат отвечает текстом на вопрос: объясняет функцию, предлагает фрагмент кода. Код из ответа человек переносит в проект сам. Помощник в редакторе встроен в VS Code: дописывает строку, пока человек печатает, объясняет выделенный фрагмент, предлагает исправление ошибки компилятора.

ИИ-агент получает задачу целиком и выполняет её по шагам: читает файлы проекта, пишет код, запускает компилятор и команды, смотрит на результат и исправляет, пока задача не будет решена или пока не кончатся попытки. Действия, которые агент может выполнять, называют инструментами: «прочитать файл», «выполнить команду», «запросить список процессов». Модель сама выбирает, какой инструмент вызвать на следующем шаге.

Сравнение из жизни

Справочное бюро отвечает на вопрос по телефону — это чат. Напарник за соседним столом подсказывает, пока вы работаете, — это помощник. Подрядчику дают задание «отремонтировать кухню», и он сам закупает материалы, нанимает мастеров и сдаёт работу — это агент. Работу подрядчика принимают по акту: проверяют каждую розетку, а не верят на слово.

Подрядчик отвечает за ремонт по договору, а за код агента отвечает тот, кто его принял, — студент.

В курсе используются все три вида, но в двух разных ролях.

§2Две роли ИИ в курсе

В первой роли ИИ помогает студенту писать агент-сторож: объясняет функции WinAPI, пишет код мозга на Python, ищет причину ошибки. Это инструмент разработчика, и его работа заканчивается, когда код сдан. Во второй роли ИИ — часть самого проекта. Он работает внутри системы после сдачи: получает тревогу, сам вызывает функции агента-сторожа, чтобы собрать подробности, и пишет человеку вывод.

Вторая роль показывает, зачем системное программирование нужно ИИ. Модель не видит компьютер. Всё, что она знает о процессах и файлах, ей сообщают функции, которые написал системный программист. Если функция вернула неполный список процессов, модель сделает неверный вывод и не заметит этого. Поэтому точность агента-сторожа проверяется отдельно от модели — нарушителем в GitHub Actions.

§3Три режима работы

У каждого задания курса указан режим: сколько работы можно поручить ИИ. Режим выбирается по цели задания. Если цель — понять новую функцию WinAPI, код пишет студент. Если функция уже понятна и нужно много однотипного кода, его может написать агент.

Без ИИР0

Студент пишет код сам. ИИ не используется.

Первый вызов каждой новой функции WinAPI, тесты, часть защиты.

ИИ объясняетР1

Студент пишет код сам, ИИ объясняет функции, ошибки компилятора и коды GetLastError, проверяет готовый код.

Ядро на C в большинстве пар.

ИИ пишетР2

Код пишет ИИ-агент по задаче студента. Студент проверяет приборами, исправляет и объясняет каждую строку.

Мозг на Python, сценарии n8n, MCP-сервер, курсовая.

В режиме Р2 студент ведёт журнал работы с ИИ: задача, которую он поставил агенту, что агент сделал, какие ошибки нашлись при проверке и как исправлены. Журнал сдаётся вместе с кодом. На защите студент объясняет любую строку, в том числе написанную агентом.

В режимах Р1 и Р2 студент принимает код от ИИ. В системном коде ошибки ИИ часто не видны при запуске, но хорошо видны приборам.

§4Ошибки ИИ в коде WinAPI

Код WinAPI, написанный ИИ, обычно компилируется и часто работает при первом запуске. Ошибки в нём другого рода: забытый размер структуры, незакрытый дескриптор, код ошибки, прочитанный слишком поздно. Такой код работает на компьютере разработчика и ломается у пользователя или через час работы. Ниже функция, которую ИИ написал по запросу «посчитай число процессов через WinAPI». В ней три ошибки. Нажмите на строку, в которой, по-вашему, ошибка.

Все три ошибки находятся приборами курса, а не чтением кода. Первая видна сразу: функция возвращает −1, а GetLastError, вызванный в правильном месте, даёт код 24 — неверная длина. Вторая видна в Process Explorer: если вызывать функцию в цикле, число дескрипторов процесса в столбце Handles растёт на единицу при каждом вызове. Третья проявляется не всегда: printf внутри вызывает функции Windows, и код ошибки может замениться другим.

В Python через ctypes у ИИ своя типичная ошибка: он не указывает, какой тип возвращает функция WinAPI. По умолчанию ctypes считает результат числом int размером 4 байта, а дескриптор в 64-битной Windows занимает 8 байт.

Если функция завершится ошибкой и вернёт INVALID_HANDLE_VALUE, в Python придёт число −1, а сравнение идёт с тем же значением, записанным как 8-байтовое число без знака. Проверка ошибки никогда не сработает, и программа пойдёт дальше с неверным дескриптором. Исправление — объявить типы до вызова: k32.CreateToolhelp32Snapshot.restype = ctypes.c_void_p и argtypes для аргументов. Эта ошибка разбирается на паре 9 вместе с ошибками памяти в C.

§5Список проверки

Код от ИИ в режимах Р1 и Р2 принимается по списку. Справа у пункта — прибор или способ проверки.

  • Результат каждой функции WinAPI проверен, GetLastError вызван сразу после неудачичтение кода
  • Каждый дескриптор закрыт на всех путях выхода из функции, включая ветки с ошибкойProcess Explorer, Handles
  • Поля размера структур заданы: dwSize, cbSize; длины буферов W-функций указаны в символахGetLastError 24, 122
  • В ctypes заданы argtypes и restype у каждой функциичтение кода
  • Сборка с AddressSanitizer проходит без сообщенийMSVC /fsanitize=address
  • Результат совпадает со служебной программой: тот же список процессов, тот же файл, тот же портSysinternals
  • Нарушитель в GitHub Actions проходит все прежние проверкиActions
  • Студент объясняет каждую строку и записал работу ИИ в журналзащита

§7Проверьте себя

Чем ИИ-агент отличается от помощника в редакторе?

Помощник отвечает на конкретную просьбу: дописать строку, объяснить фрагмент. Агент получает задачу целиком и выполняет её по шагам: сам читает файлы, запускает компилятор и команды, смотрит на результат и исправляет, выбирая следующий инструмент.

Почему точность агента-сторожа проверяется отдельно от модели ИИ?

Модель видит компьютер только через функции агента. Если функция вернула неполные данные, модель сделает вывод по ним и ошибки не заметит. Поэтому данные агента сверяются со служебными программами и нарушителем, а вывод модели — с данными агента.

ИИ написал функцию, которая работает при запуске. Как проверить, что в ней не теряются дескрипторы?

Вызвать функцию в цикле и смотреть в Process Explorer столбец Handles у процесса. Если число растёт с каждым вызовом, какой-то дескриптор не закрывается.

Почему в режиме Р0 пишется первый вызов каждой новой функции WinAPI?

Чтобы студент сам разобрался с аргументами, структурами и кодами ошибок этой функции. Без этого он не сможет проверить код, который ИИ напишет с той же функцией в режиме Р2.

Итог главы

Чат отвечает текстом, помощник работает в редакторе, агент выполняет задачу по шагам с инструментами. В курсе ИИ работает в двух ролях: помощник разработчика с первой пары и агент внутри проекта, который объясняет и расследует тревоги через функции агента-сторожа. Режим задания — Р0, Р1 или Р2 — определяет, сколько работы можно поручить ИИ. Ошибки ИИ в коде WinAPI находятся приборами: Process Explorer, AddressSanitizer, коды GetLastError, сверка со служебными программами. Код принимается по списку из восьми пунктов, и за каждую строку отвечает студент.
