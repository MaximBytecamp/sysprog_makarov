§1Чему учит дисциплина

Дисциплина длится 24 пары. За это время невозможно научиться писать драйверы или ядро, поэтому цель другая: понять, что происходит внутри операционной системы, когда работает программа, научиться получать эти сведения из своего кода, проверять их служебными программами и отдавать другим программам, в том числе моделям ИИ. Все темы курса собираются в один проект, который к концу семестра работает как настоящий агент мониторинга с ИИ-расследованием тревог.

После дисциплины студент должен уметь шесть вещей:

  1. Объяснить, что происходит внутри системы во время работы программы: процессы и потоки, виртуальная память, файлы и реестр, сетевые соединения, службы.
  2. Писать на C код, который вызывает системный интерфейс — WinAPI в Windows, POSIX и собственные функции в Linux и macOS, — и разбирать ошибки этих вызовов по кодам GetLastError и errno.
  3. Связывать C и Python: собирать динамическую библиотеку на C и вызывать её из Python через ctypes, связывать два процесса именованным каналомUnix-сокетомUnix-сокетом.
  4. Проверять результат приборами: Process Explorer, Process Monitor, Autoruns, TCPView, отладчиком x64dbgМониторингом системы, lsof, fs_usage, vmmap, отладчиком lldb/proc, strace, ss, journalctl, отладчиком gdb, AddressSanitizer.
  5. Работать с ИИ и встраивать его в систему: ставить задачу ИИ-агенту и принимать его код по списку проверки, давать модели инструменты для расследования, писать MCP-сервер.
  6. Защитить проект: показать агент в работе, объяснить любую строку кода, в том числе написанную ИИ.

§2Классический план и план курса

В классическом плане этой дисциплины лекции пересказывают теорию операционных систем, а практика проходит в Windows Forms. Windows Forms — библиотека .NET для окон, кнопок и списков. Она берёт обращения к системе на себя: строка Process.GetProcesses() возвращает готовый список процессов, а как Windows его собирает, программист не видит. В результате теория остаётся текстом лекции, а практика учит располагать элементы на форме, то есть прикладному программированию.

Сравнение из жизни

Пультом от телевизора пользоваться удобно, но по нему не узнать, как устроен телевизор. Чтобы разобраться, нужно снять заднюю крышку и проверить плату прибором. Windows Forms — это пульт. В курсе роль снятой крышки играет системный интерфейс — WinAPI или POSIX, — а роль прибора — служебные программы системы и отладчик.

Снятая крышка телевизора лишает гарантии, а системные вызовы — обычный способ работы с системой, ими пользуются сами её разработчики.

В курсе каждая тема теории проверяется на настоящем компьютере. В таблице одна и та же тема в двух планах. Правая колонка показана для выбранной системы.

§3Агент-сторож: ядро на C и мозг на Python

Агент мониторинга — программа, которая постоянно работает на компьютере, собирает сведения о его состоянии и сообщает о нарушениях. Такие программы есть в каждой организации, где больше нескольких компьютеров: агент Zabbix следит за нагрузкой серверов, Защитник Windows — за подозрительными файлами, системы инвентаризации — за установленными программами.

Сравнение из жизни

Охрана здания состоит из датчиков и дежурного. Датчики на дверях и окнах простые и быстрые: они только сообщают, что дверь открылась. Дежурный получает сигналы, сверяет их с расписанием, звонит начальнику и вызывает наряд. Датчики не умеют звонить, а дежурный не может стоять у каждой двери.

Датчики охраны ставит монтажник, а ядро и мозг агента пишет один и тот же студент.

Агент курса состоит из двух частей, и каждая написана на том языке, который для неё удобнее. Ядро написано на C. Оно вызывает системные функции и возвращает факты: список процессов, загрузку процессора, хэш файла, записи автозагрузки, открытые порты, подпись программы. В ядре нет расписания, сети и ИИ, только точные и быстрые вызовы системы. Для каждой системы у ядра своя реализация, а набор функций и формат ответа одинаковые, поэтому мозг на Python работает на всех трёх системах без изменений. Мозг написан на Python. Он по расписанию вызывает функции ядра, сравнивает результат с прошлым снимком, решает, что считать нарушением, отправляет тревоги в n8n и отвечает на запросы ИИ-агента.

Связь частей меняется по ходу курса. Сначала ядро собирается в динамическую библиотеку — sentry_core.dlllibsentry_core.dyliblibsentry_core.so, — и Python вызывает её функции через ctypes в своём процессе. В конце курса ядро становится службой Windowsдемоном launchdслужбой systemd, а мозг — отдельным процессом, который связывается с ним по именованному каналучерез Unix-сокетчерез Unix-сокет. Переключатель в заголовке схемы показывает четыре этапа.

Ядро на C отвечает за точность данных, мозг на Python — за решения и связи с другими программами. Если модель ИИ сделала неверный вывод, сначала проверяется, верные ли данные ей дало ядро. Поэтому ядро проверяется нарушителем и служебными программами отдельно от модели.

§6Как растут проверки

Сравнение из жизни

Инструктор по вождению сначала проверяет только трогание с места, потом добавляет повороты, парковку, движение в потоке. На экзамене маршрут включает всё сразу, и трогание с места из него не исчезает.

На экзамене по вождению маршрут один, а здесь нарушитель после каждой пары получает новую ситуацию, и старые ситуации проверяются заново.

В репозитории студента настроен GitHub Actions — автоматический запуск на серверах GitHub. Проверка идёт сразу на трёх серверах: windows-latest, macos-latest и ubuntu-latest. После каждой отправки кода серверы собирают ядро, запускают мозг и программу-нарушитель. Нарушитель по очереди создаёт ситуации из пройденных тем: запускает процесс, который загружает процессор, меняет файл hosts, добавляет запись в автозагрузку — каждую так, как это делается в данной системе. Мозг должен выдать тревогу на каждую. Студент сдаёт ядро для своей системы, а зелёная отметка на всех трёх серверах даёт дополнительные баллы. Нарушитель проверяет тревоги, а не язык и не текст модели, поэтому код можно писать с ИИ в разрешённом режиме, но работать он должен точно.

Ползунок ниже выбирает пару. Цветная полоса под клеткой — модуль, ромбик над клеткой — пара, на которой появляется новая проверка.

После модулей 2, 3, 4 и 5 проходит тест по их темам — на парах 9, 13, 19 и 22. Курсовая работа собирается из агента со всеми проверками, поэтому к паре 23 она почти готова: остаётся добавить одну свою проверку и один свой инструмент для ИИ-агента, отчёт и защиту.

Что нужно для работы

Windows 10 или 11, права администратора: они нужны для служб, журнала безопасности и Process Monitor.macOS 13 или новее, пароль администратора: он нужен для fs_usage, системного журнала и демонов launchd.Ubuntu 22.04 или новее (подойдут и другие дистрибутивы), права sudo: они нужны для strace чужих процессов, журнала входов и служб systemd. Оперативной памяти — от 8 ГБ: на 8 ГБ работает модель на 1–3 млрд параметров, на 16 ГБ — до 8 млрд; ИИ-агенту с инструментами на 8 ГБ лучше дать облачную GigaChat. Модели, n8n и программы для кабинета скачиваются заранее и раздаются из общей папки, поэтому при плохом интернете работает всё, кроме GitHub и облачных моделей.

§9Задание к модулю 0

Одна системная функция из C и из Python · Р1 · сдаётся файлами hello.c, hello.py и report.md

Нужно установить компилятор, собрать программу из главы 0.1, вызвать ту же функцию из Python и найти оба процесса в служебной программе своей системы. Помощник ИИ объясняет программу по строкам, объяснение сверяется с главой 0.1. Шаги ниже показаны для системы, выбранной переключателем вверху страницы.

  1. Установите компилятор

    Откройте страницу visualstudio.microsoft.com/downloads, в разделе Tools for Visual Studio скачайте Build Tools for Visual Studio. В установщике отметьте рабочую нагрузку Разработка классических приложений на C++ (Desktop development with C++) и нажмите Установить. Python 3.14 скачайте с python.org и при установке отметьте Add python.exe to PATH.

    Место под кадр с компьютера в классе

    Visual Studio Installer, вкладка «Рабочие нагрузки»: отмечена «Разработка классических приложений на C++», справа в списке компонентов отмечены MSVC и Windows 11 SDK.

  2. Откройте командную строку компилятора

    В меню «Пуск» найдите x64 Native Tools Command Prompt for VS. В этой командной строке настроены пути к компилятору; в обычной командной строке и в PowerShell команда cl не найдётся.

  3. Создайте файл программы на C

    Выполните команды и вставьте в Блокнот код ниже. Блокнот спросит, создать ли новый файл, — ответьте «Да».

  4. Скомпилируйте и запустите программу

    Первая строка вывода cl — название и версия компилятора, например Microsoft (R) C/C++ Optimizing Compiler Version 19.44…. Программа напечатает agent v0, pid=… и будет ждать Enter. Откройте Диспетчер задач, вкладку Подробности, найдите hello.exe и сравните число в столбце ИД процесса с выводом. Затем нажмите Enter.

    Место под кадр с компьютера в классе

    Слева командная строка с выводом «agent v0, pid=…», справа Диспетчер задач на вкладке «Подробности», строка hello.exe с тем же ИД процесса выделена.

  5. Вызовите ту же функцию из Python

    Создайте рядом файл hello.py и запустите его командой python hello.py. В Диспетчере задач найдите процесс python.exe с напечатанным номером.

  1. Установите компилятор

    Откройте Терминал и выполните команду ниже. Появится окно установки Command Line Tools — нажмите Установить. В набор входят компилятор clang, отладчик lldb и git. Python 3.14 скачайте с python.org.

  2. Создайте файл программы на C

    Если файла ещё нет, создайте его командой touch hello.c перед open -e. Вставьте код в TextEdit и сохраните.

  3. Скомпилируйте и запустите программу

    Первая строка вывода clang --version — версия компилятора, например Apple clang version 17.0.0. Программа напечатает agent v0, pid=… и будет ждать Enter. Откройте Мониторинг системы, найдите процесс hello и сравните число в столбце PID с выводом. Затем нажмите Enter.

  4. Вызовите ту же функцию из Python

    Создайте рядом файл hello.py и запустите его командой python3 hello.py. Процесс с напечатанным номером найдите командой ps -p <номер> в другом окне Терминала.

  1. Установите компилятор и Python

    В Ubuntu и Debian компилятор gcc, make и заголовочные файлы входят в пакет build-essential. В других дистрибутивах пакет называется иначе, например base-devel в Arch.

  2. Создайте файл программы на C

    Вставьте код, сохраните сочетанием Ctrl+O и выйдите Ctrl+X.

  3. Скомпилируйте и запустите программу

    Первая строка вывода gcc --version — версия компилятора. Программа напечатает agent v0, pid=… и будет ждать Enter. В другом окне терминала выполните ps -p <номер> -o pid,comm или найдите процесс hello в htop. Затем нажмите Enter.

  4. Вызовите ту же функцию из Python

    Создайте рядом файл hello.py и запустите его командой python3 hello.py. Найдите процесс с напечатанным номером тем же способом.

  1. Спросите помощника ИИ (режим Р1)

    Откройте hello.c в VS Code с помощником GigaCode, SourceCraft или Continue и попросите: «Объясни эту программу по строкам. Что делает функция, которая возвращает номер процесса, и зачем getchar?». Сравните ответ с главой 0.1, §4 и выпишите в отчёт одно место, где ответ помощника точнее или менее точен, чем глава.

Отчёт report.md содержит систему и версию компилятора, выводы hello и hello.py, номера процессов из служебной программы, запрос к помощнику и сравнение его ответа с главой. Файлы войдут в репозиторий курса на паре 2.

Если компилятор пишет, что не находит windows.h

В установщике не отмечен Windows SDK. Откройте Visual Studio Installer, нажмите «Изменить» у Build Tools и отметьте в рабочей нагрузке C++ пункт Windows 11 SDK.

Если команда clang пишет, что не найдены инструменты разработчика

Command Line Tools не установлены или установлены не до конца. Повторите xcode-select --install и дождитесь окончания установки; путь к инструментам показывает команда xcode-select -p.

Итог главы

Дисциплина учит понимать, что происходит внутри операционной системы во время работы программы, получать эти сведения из кода на C через системный интерфейс, проверять их приборами и отдавать моделям ИИ. Курс идёт для трёх систем: Windows, macOS и Linux. Весь курс студенты пишут агент-сторож: ядро на C вызывает системные функции, мозг на Python принимает решения и связывает агент с n8n, ИИ-агентом и MCP. ИИ участвует с первой пары тремя линиями: помощник разработчика, модель, которая объясняет тревоги, и ИИ-агент, который их расследует. За 24 пары агент получает 13 проверок, и нарушитель в GitHub Actions подтверждает их все на трёх системах после каждой отправки кода. Курсовая работа — агент со всеми проверками, своей проверкой, своим инструментом для ИИ-агента и защитой.
