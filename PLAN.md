# Справочник по системному программированию — карта книги

Каркас книги — справочники по MongoDB и по Angular и React (корешок, лист, паспорт главы,
«В этой главе», «Проверьте себя», итог, источники). Палитра своя: бирюзовый `#0B7A75` —
режим пользователя и код курса, янтарный `#B8650A` — ядро и предупреждения.

## Принцип

24 пары. **Три системы: Windows, macOS, Linux** (решение автора 26.10.2026): переключатель `data-os` в `book.js`
(ключ `sp-book-os`, событие `book:os` для перерисовки схем). Гибрид C и Python: ядро агента на C вызывает системный
интерфейс — WinAPI или POSIX + свои функции (`sentry_core.dll` / `libsentry_core.dylib` / `libsentry_core.so`, с пары 20 —
служба Windows / демон launchd / служба systemd), мозг на Python (`brain.py`) вызывает ядро через `ctypes`,
принимает решения, шлёт тревоги в n8n, отдаёт инструменты ИИ-агенту и работает MCP-сервером.
Каждая тема в три шага: WinAPI на C → сверка со служебной программой → новая проверка.
13 проверок, нарушитель в GitHub Actions на windows-latest, macos-latest и ubuntu-latest проверяет тревоги, а не язык.
Студент сдаёт ядро для своей системы; зелёная проверка на всех трёх — дополнительные баллы (предложение, не утверждено).
Аналоги проверок: автозагрузка — ключ Run / LaunchDaemons / systemd и cron; папка — Startup / LaunchAgents / ~/.config/autostart;
подпись — Authenticode / codesign / «не из пакета или из /tmp».

ИИ с первой пары, три линии (глава 0.3): помощник разработчика (GigaCode, SourceCraft, Continue+Ollama)
в режимах Р0/Р1/Р2; модель в сценарии n8n объясняет тревоги с пары 3; ИИ-агент в проекте —
инструменты (16), расследователь в n8n (17), MCP-сервер (19). OpenAI, Anthropic, Google не используются:
недоступны из России.

## Лабораторные работы (решение автора 26.10.2026)

Каждая пара начинается с лабораторной в программах системы, как в ОП.03: шаг = действие → кадр → «что на кадре» →
«что изменилось» → «в отчёт». Порядок пары: лабораторная (~35 мин) → устройство (~15) → ядро агента (~30) → ИИ (~10).
Карта 24 лабораторных — `tools/labs.py` (источник для 0.4 §7 и §9, обложки). Сборка страницы — `tools/lab_build.py`
(блоки по системам через data-os), данные ЛР 1 — `tools/lab1.py` → `temy/05-laboratornaya-1`.

Кадры Linux снимаются в ВМ Ubuntu-lab-01 (Ubuntu 24.04 Live, ARM, английский интерфейс) скриптом `~/sysprog-shots/v.py`
(основа — `~/op05-shots-work/vm.py`; только клавиатура: кнопка End Process нажимается через Tab-порядок,
Ctrl+E в GNOME System Monitor 46 не работает). Сырые кадры — `~/sysprog-shots/raw`, рамки и номера наносятся при экспорте.
Кадры Windows и macOS пока — блоки `.shot-todo` с точным описанием кадра.
Кадры macOS ЛР 1 сняты на Mac автора (macOS 26.1, русский интерфейс) скриптами `tools/cap.py` и `tools/mac.py`: окна Терминала
и Мониторинга системы снимаются по номеру окна (`screencapture -l`), без фона экрана, и склеиваются рядом. Команды в Терминал —
`do script ... in window id` (без вывода окна вперёд), поиск в Мониторинге — через специальные возможности. Пользователь просит
снимать в фоне, без переключения окон: не вызывать `activate` и не отправлять нажатия клавиш.
Кадры Windows ЛР 1 сняты в ВМ Win11-lab (Windows 11 24H2 ARM64, русский, собрана из UUP dump, VirtualBox 7.2, контроллер xHCI —
с OHCI клавиатура не работает, диск на SATA — VirtIO установщик не видит; NAT DNS не работает, интернет через `tools/proxy.py`
на хосте 10.0.2.2:8899). В ВМ Build Tools 2022 (MSVC 19.44, x64 через эмуляцию), Python 3.14 ARM64, Process Explorer.
Ввод — `tools/w.py` (скан-коды, переключение окон Win+цифра по панели задач). В тексте отмечено, что x64 работает через xtajit64.

## Шаблон репозитория студента

`MaximBytecamp/sysprog-start-template` (исходник `~/sysprog-start-template`, свой git), репозиторий студента — `sysprog-start`.
По образцу python-start-template: `labs/NN-…` (README, report.md с ___), `agent/core` (C) и `agent/brain` (Python),
`homework/`, `exams/`, `lectures/` (конспекты из итогов глав), `materials/`, `docs/SUBMIT.md` и `UPDATES.md`,
ежедневное обновление `update-materials.yml` (к файлам преподавателя добавлена папка `checks/`).
Проверки: `.github/workflows/checks.yml` — матрица windows/macos/ubuntu, Python 3.14, MSVC через ilammy/msvc-dev-cmd,
вся логика в `checks/run_checks.py` (файл преподавателя, обновляется сам): ЛР 1 собирает hello.c своей системы,
13 проверок агента с `OPENED = 0`. Новая пара = строка в labs/README.md + папка работы + конспект + OPENED.
На обложке книги — карточки шаблона и, без изменений, «Работа с репозиторием по шагам» и «Стандарт» с ДУП.02.
